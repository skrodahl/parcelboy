## Decisions
- (2026-09-30) Git branch is `master` (git default); kept as-is.
- (2026-09-30) M0 kept renderer setup inline in `main.js`; it moves to `render/renderer.js` in M1 when quality presets land.
- (2026-09-30) `three.module.js` @ 0.170.0 is self-contained (grep for `three.core` found no import, per the M0 check), so only one vendored file is needed.
- (2026-09-30) `voxel.js` originally emitted the 2nd triangle of each face as `(v1,v3,v2)`, which is wound **inward** (back-face). In a `FrontSide` material that triangle is culled → the "triangular holes" I first misread as "SwiftShader drops triangles" (it reproduces on any backend). A `DoubleSide` workaround hid the holes but rendered those triangles as back faces with flipped normals → the "comb" shading streaks on the roof. **Fix:** index split is now `base, base+1, base+2, base, base+2, base+3` (all triangles CCW); `worldMat` reverted to the correct `FrontSide` (saves fill vs DoubleSide). Verified clean on SwiftShader and Chromium.
- (2026-09-30) Stacked boxes use `skipFaces:['bottom']` to avoid coplanar z-fighting (never leave two large faces in the same plane).
- (2026-09-30) M1 test scene: the house casts but does not receive its own shadow (the ground receives the house shadow); real static-chunk self-shadowing is handled in M2. Shadow camera extent `max(14, 5.2/tan(sunElev)+6)`, bias −0.0008, near 5 / far 160.
- (2026-09-30) M2: the M0/M1 scenes are now opt-in (`?scene=test`, `?scene=cube`); the default scene is the built neighborhood world. `m0-cube` shot URL is now `/?scene=cube&debug=1&mute=1`.

- (2026-09-30) M2: per-tile slabs get a checkerboard top-face depth offset (0.005, `((x+z)&1)`) so coplanar jittered tile tops never z-fight; slabs span `SLAB_BASE=-0.4` up to the surface height (curbs raised to 0.12).
- (2026-09-30) M2: world shadow camera was set with `top`/`bottom` swapped (±110); fixed to `top=110, bottom=-110`.

- (2026-09-30) M2: sign atlas (§7.8) built with 2 columns, auto-fit font (`measureText`), and plate-only UV sub-rects so a sign quad shows just the plate (first attempt mapped the whole slot → cream background showed; font also overflowed the plate → garbled text; both fixed). Sign posts merge into chunk opaque builders; all sign quads merge into one mesh + one `MeshBasicMaterial` (1 call, 1 texture).
- (2026-09-30) Push target: GitHub repo `skrodahl/parcelboy`, branch `main` (local branch renamed `master` → `main` to match; user instruction 2026-09-30).
- (2026-09-30) **M3 glow (§7.3/§7.4):** all window/lamp/lit-sign glow is ONE shared `MeshBasicMaterial({vertexColors:true})` mesh. `GlowBuilder` records a *day* and a *night* color per vertex; `toGeometry()` bakes the active time-of-day color (via `__setGlowBlend(preset.glow)`, a 0..1 lerp) into the `color` attribute. A time-of-day change re-lerps the attribute in place (cheap, no new geometry); the day-cycle in M10/M11 calls the same hook. This satisfies "color multiplier changes with time of day" without a per-mesh material.
- (2026-09-30) **M3 sign atlas (§7.8) full layout:** one 1024² canvas. Top 3 rows = up to 12 wide sign plates (4×256px slots) — 7 streets, 3 shops (accent bg), QUICKBOX, HOLLOW ELEMENTARY. Bottom row = a 4×4 grid of 64px number tiles (mailbox numbers) in the left slot + the Quickbox logo tile in the right slot. All sign quads (street/shop/depot/mailbox/van-logo) share UV sub-rects of this one atlas → one mesh + one `MeshBasicMaterial` (1 call, 1 texture). Nothing is drawn into two slots (an earlier draft had the number grid + logo collide with plate slots — fixed by reserving the bottom row).
- (2026-09-30) **M3 sign quad winding/UV:** the generic quad builder computes a horizontal tangent as `cross(faceNormal, up)`. First cut used `vert=[0,0,1]` for horizontal faces, which makes ±Z faces degenerate (cross → 0) and mirrored the text. Fixed: `vert` is always `[0,1,0]` (signs are vertical), and the UV left/right edges are assigned to the `±tangent` corners so text reads correctly (verified on the mailbox "3" and the depot QUICKBOX sign).
- (2026-09-30) **M3 school flag (§6.4):** the flag is a small merged geometry (brand panel + accent patch) built in the school's local frame, merged into the chunk, and waved by rotating the whole geometry's parent mesh `rotation.y = sin(t)·0.3` (allocation-free) around the pole. One extra mesh, no extra material/texture.
- (2026-09-30) **M3 lamp light pools (§7.3):** lamps at dusk are emissive glow heads (in the glow mesh) plus a flat, soft, additively-blended ground disc. Pools are ONE merged quad mesh (1 draw call) using a 128px radial-gradient canvas texture; the mesh is hidden when `preset.glow == 0`. This is the "one more tiny canvas texture" from §7.8, shared later with M4's blob shadows (total textures stay ≤ 4; dusk shots show tex=3 = atlas + shadow map + pool texture).
- (2026-09-30) **M3 parked cars:** ~40% of driveways get a static sedan (seeded pick), each a few merged boxes in a `VoxelBuilder` per car, merged into the owning chunk's opaque builder with a box collider registered. No per-frame cost; colors from the §7.6 car palette.
- (2026-09-30) **Plan change 2026-09-30 (fog/tone/overview):** (1) `renderer.toneMapping = NeutralToneMapping` (ACES flattened the pastels). (2) Fog near/far and the camera far plane now scale with the camera's distance `d` to its look target, updated every frame with no allocation: `fog.near=d+45`, `fog.far=d+150`, `camera.far=max(220,d+260)` (`updateProjectionMatrix()` only when far changes). A `camLook` scratch vector records the current preset's look point. The sky dome already used `depthWrite:false` + `renderOrder=-1` (kept). (3) The `overview` preset was re-framed to `pos [cx,170,cz+130] → look [cx,0,cz-4]` so the whole 48×40 map including the south strip (park + Distribution Center) is in frame. Re-shot m2-* and m3-*: the overview no longer fades the far half into sky (d≈216 → near 261/far 366, almost no fog at map scale) and colors read more saturated under Neutral. This resolves the M2 "north half fades" known issue early.
